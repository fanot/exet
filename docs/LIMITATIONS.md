# Известные ограничения и допущения

Актуальные результаты проверки и обнаруженные расхождения с прежними заявлениями: [аудит 25.09.2026](AUDIT_2026-09-25.md). Успешная проверка относится к математической модели и входным данным, а не к сертификации реального полета.

## Модель и данные

- **Энергия.** По умолчанию модель линейная по времени полета (QA: «линейной модели будет достаточно»). Опционально доступна модель, откалиброванная по открытой телеметрии: коптер — по воздушной скорости, набору/снижению и разгонам; самолет — по набору/снижению и крену. Ее допущения описаны в [ENERGY_MODEL.md](ENERGY_MODEL.md). Зависимость от температуры не моделируется, за нее отвечает резерв 20%. Для Геоскан 201 дополнительно ограничена протяженность маршрута (210 км).
- **Ветер** — одно значение на всю миссию (замер у земли), пересчитанное на высоту по степенному профилю. Изменение ветра по ходу работ не учитывается (QA: борт замеряет ветер в начале полета). По умолчанию (методика QA) расход АКБ и путевая скорость от ветра не зависят. Это упрощение организаторов: при сильном встречном ветре реальная путевая скорость ниже. Для консервативной оценки есть режим `wind_model=physical`.
- **ТТХ, отсутствующие в материалах**, приняты допущениями и помечены в `planner/catalog.yaml` полем `assumption`:
  - шаг пикселя тепловизора 801 — 12 мкм;
  - размер матрицы камеры 801 — 1/2.3″;
  - время зарядки АКБ 201 — 240 мин;
  - число АКБ на борт;
  - буферы маневра;
  - лидар и магнитометр — типовые, в линейке задачи их нет.
- **Кинематика.** Самолет упрощен (QA: «защитные буферные зоны маневрирования»):
  - развороты — вынос плюс дуга радиуса R = V²/(g·tg30°);
  - набор и снижение — спираль;
  - посадка — спираль до 100 м и парашют без сноса.

  Коптер: вертикальные взлет и посадка, торможение и разгон на разворотах.
- **ЦМР** — открытые тайлы Terrarium z12 (~20 м/пикс в районе демо). Шаг профиля 25 м, на сложных переходах до 10 м. Абсолютная точность для конкретного района не измерена. Если запрошенная ЦМР недоступна, итоговая проверка не проходит; плоская модель разрешена только при явном `use_terrain=false`. Для большой территории уровень тайлов понижается. ЦМР Web Mercator не покрывает широты за ±85.05°.
- **Высотные препятствия** задаются высотой верха AGL либо абсолютной отметкой AMSL. Вертикальный запас — 30 м для коптеров, 100 м для 201 по руководству, горизонтальный буфер — 30 м. Нарушение запаса приводит к отказу проверки. Потолки модели, облачность и общий коридор ограничивают и съемку, и перелеты.

## Запретные зоны

- **Площадка внутри постоянной запретной зоны** не используется, если есть другие площадки. Если все площадки заблокированы, план не может получить статус `ok`.
- **Режим без плана полета.** Сервис контролирует заданный потолок 150 м, удаление от площадки и светлое время. Это расчетный режим, не подтверждение юридической допустимости полета. Дополнительные ограничения нужно передать слоями. Радиус видимости — параметр (2 км по умолчанию), геометрическая видимость за рельефом не проверяется. Невозможный коридор над рельефом под потолком отклоняется.

- **Высотный диапазон.** Зона, нижняя граница которой выше рабочих высот, не блокирует съемку, но опускает потолок эшелонов. Зоны с нижней границей в диапазоне съемки считаются блокирующими по всей высоте (консервативно).
- **Временные ограничения без времени действия** (все «врем_ограничение» в примере организаторов) по умолчанию считаются действующими весь период работ; отключаются параметром `temp_restrictions=ignore`, если действие проверено по NOTAM. Эшелоны FL переводятся в метры как высота над уровнем моря при стандартном давлении — погрешность в десятки метров не важна для зон выше 1 км. Исключения из текста зоны («не распространяется на государственную авиацию…») не применяются — показываются в подписи зоны.
- **Временные зоны.** Вылет, чья траектория задевает зону, целиком ставится вне ее окна действия. Это консервативно: частично ранний вылет не планируется.
- Зоны, закончившие действие до старта, не учитываются. Будущие зоны сохраняются и для многодневных миссий; отсечения по 48 ч нет.
- Достижимость посадки подтверждается оставшейся частью проверенного маршрута к назначенной основной площадке. Отдельный кратчайший аварийный маршрут к резервной площадке не рассчитывается.
- При нескольких полигонах `airspace` применяется минимальный из их потолков ко всему объединению. Это консервативное упрощение, а не полноценная кусочная модель 3D-пространства.

## Площадки и парк

- **Автоматические площадки** ставятся по геометрии: подъезд, покрытие и уклон местности не проверяются — их нужно подтвердить на месте. Площадку можно сдвинуть или поставить вручную на карте.
- **Подбор парка к сроку** опирается на быструю оценку (без 4D-разведения). Рекомендованный парк нужно рассчитать полностью, это делается одной кнопкой. Время работ ступенчато зависит от числа бортов из-за светового дня.
- **Ресурс до ТО** — доля межсервисного интервала: у 201 по полетам (80), у коптеров по часам (160). Интервал Gemini организаторы не назвали, он принят как у 801.
- **Крупные разрозненные задания** (сотни участков на десятках километров) считаются минутами, а не секундами. Самолету достаются дальние разрозненные участки с большой долей перелета.

## Алгоритм

- Решение эвристическое, без гарантии глобального оптимума:
  - поиск по долям площади и ширине колонок;
  - жадная упаковка вылетов;
  - list scheduling;
  - финальный отбор из 3 лучших вариантов полным построением.

  Журнал поиска (`search_log`, `final_candidates`) сохраняется в плане.
- Полный независимый валидатор запускается после выбора финального кандидата. Если кандидат нарушает ограничение, возвращается `infeasible`; повторный поиск с исключением этого кандидата пока не выполняется. Отказ не доказывает математическую невозможность задачи.
- `coverage_allowed_pct` — площадь объединения расчетных полос. Это не независимая фотограмметрическая проверка проекций каждого снимка, фактических перекрытий, смаза и GSD. Профиль съемки упрощается с допуском 3 м; возможное изменение GSD на неровной местности следует оценивать отдельно.
- Изогнутые и невыпуклые области (коридоры с поворотами, «Г»-образные участки) режутся на почти выпуклые части, у каждой свой курс галсов. Разрез идет поперек длинной оси и выбирается из нескольких положений, глубина рекурсии ограничена 5. Для очень извилистых объектов (река, серпантин) части могут оставаться неидеальными.
- Взлет и посадка одного вылета — на одной площадке (QA допускает разные). Переезды расчета между площадками учитываются в расписании.
- Разведение бортов выполняется задержкой старта на земле. Изменение маршрута в воздухе для разведения не используется: это проще и безопаснее, но иногда увеличивает время.
- Площадки считаются неограниченной вместимости (QA). Порядок взлетов с одной площадки разводится по времени автоматически.
- Для площадей ≫ 200 км² и >10 бортов время расчета растет (4D-проверка — O(вылеты × пересечения по времени)). Режим «быстро» остается в пределах минут.

## Инфраструктура

- История планов хранится в файлах (`data/plans`), аутентификации нет (QA: необязательно).
- API запускает отдельный поток на расчет; лимит одновременных расчетов и срок хранения записей задач не заданы. Для общего сервера нужны очередь/лимиты. Крупные кэши завершенного планировщика освобождаются.
- Для подложки карты и ЦМР нужен интернет (QA: «считайте, что интернет есть»). Рассчитанные планы экспортируются и работают офлайн.
- Сборка Docker проверена на уровне Dockerfile. На машине разработчика Docker Hub был недоступен, поэтому базовый образ можно переопределить: `BASE_IMAGE=mirror.gcr.io/library/python:3.11-slim docker compose up --build`.
- Абсолютные отметки препятствий (eTOD, `altitudeMode=absolute`) переводятся в высоту над землей по ЦМР ~20 м. Без ЦМР отметка трактуется как высота над землей — это консервативно. Независимый валидатор сравнивает абсолютную отметку с абсолютной высотой борта напрямую, без ЦМР.
- Geoscan Planner 2.5 (установщик под Windows) в среде разработки (macOS) не запускался. Импорт наших KML в Planner не проверен.
- Совместимость с Geoscan Planner не требуется (QA). Экспорт в QGroundControl `.plan` сделан как бонус, высоты AMSL. Загрузку в симулятор мы не проверяли.
