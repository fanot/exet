# Формат зон ограничений: высоты и время действия

В примере организаторов (`Московская зона.kml`) диапазон высот записан текстом (`Altitudes`), время действия
временных ограничений не указано вовсе. Организаторы просят: «В файле нет стандартного формата записи данных
о диапазоне высот и времени действия ограничения. Предложите свой».

Ниже — предлагаемый формат. Сервис его читает, а старый текстовый формат разбирает автоматически, поэтому оба
варианта можно смешивать в одном файле.

## Поля (GeoJSON `properties` или KML `ExtendedData/Data`)

| Поле | Значение | Пример |
|---|---|---|
| `kind` | `no_fly` — зона ограничения | `no_fly` |
| `category` | `P` — запретная зона, `R` — зона ограничения полетов, `TEMP` — временное ограничение | `TEMP` |
| `alt_min_m` | нижняя граница, м; пусто — от земли | `800` |
| `alt_max_m` | верхняя граница, м; пусто — без ограничения | `2743` |
| `alt_ref` | отсчет обеих границ: `AGL` — от земли, `AMSL` — от уровня моря. Эшелон FLnnn записывается как `AMSL`: nnn·100 фут × 0.3048 | `AMSL` |
| `active_from`, `active_to` | время действия, ISO 8601 с часовым поясом; пусто — постоянно | `2026-09-25T10:00:00+03:00` |
| `name` | обозначение зоны | `UUR215` |
| `note` | исходный текст и исключения («не распространяется на…») — сохраняется и показывается в интерфейсе | |

Если у зоны несколько интервалов действия (по дням), она записывается несколькими объектами с одной геометрией.

### KML

```xml
<Placemark>
  <name>UUR203</name>
  <ExtendedData>
    <Data name="kind"><value>no_fly</value></Data>
    <Data name="category"><value>TEMP</value></Data>
    <Data name="alt_min_m"><value>700</value></Data>
    <Data name="alt_max_m"><value>8534</value></Data>
    <Data name="alt_ref"><value>AMSL</value></Data>
    <Data name="active_from"><value>2026-09-25T10:00:00+03:00</value></Data>
    <Data name="active_to"><value>2026-09-25T16:00:00+03:00</value></Data>
    <Data name="note"><value>От 700 м (2300 фут) AMSL до FL280</value></Data>
  </ExtendedData>
  <Polygon>…</Polygon>
</Placemark>
```

### GeoJSON

```json
{"type": "Feature", "geometry": {"type": "Polygon", "coordinates": [[...]]},
 "properties": {"kind": "no_fly", "category": "P", "name": "UUP400", "alt_max_m": 900, "alt_ref": "AMSL",
                "note": "От земли до 900 м (3000 фут) AMSL"}}
```

## Как читается текущий формат организаторов

`Type`:
- `запретная_зона` → `P`;
- `пост_ограничение` → `R`;
- `врем_ограничение` → `TEMP`;
- `svo` → особый режим на всех высотах.

`Altitudes` (текст):

| Текст | Результат |
|---|---|
| «От земли до 900 м (3000 фут) AMSL» | от земли до 900 м AMSL |
| «От земли до 500 м (1700 фут) AGL» | от земли до 500 м AGL |
| «От 800 м (2700 фут) AMSL до FL90» | 800–2743 м AMSL |
| «От FL280 до FL400» | 8534–12192 м AMSL |
| «На всех высотах», «GND-UNL», «SVO», «По описанию военных», пусто | все высоты (консервативно) |

Префикс «Некорректная геометрия!» отбрасывается, контур исправляется (`make_valid`). Текст после первой строки
(исключения) сохраняется в `note`.

## Как зона учитывается

- **Нижняя граница выше коридора полетов.** Зона не влияет. Для `AMSL` нижняя граница пересчитывается в высоту над землей по максимуму рельефа под зоной в районе работ (консервативно). Пример: UUR215 «от FL150» над заданием — не мешает.
- **Нижняя граница выше рабочих высот, но ниже коридора.** Съемка под зоной разрешена, эшелоны перелета ограничиваются снизу зоны.
- **Иначе** зона вырезается из области съемки, перелеты обходят ее по графу видимости.
- **Временные ограничения с `active_from/active_to`** — вылеты, чья траектория задевает зону, ставятся вне окна действия.
- **Временные ограничения без времени действия** (все `врем_ограничение` в примере): по умолчанию считаются действующими весь период работ. Если их действие проверено по NOTAM или плану ИВП, параметр `temp_restrictions="ignore"` отключает их — и в планировщике, и в независимой проверке.
- **Файл зон на несколько областей** (341 зона) обрезается по району работ: в примере рядом с заданием 17 зон.
