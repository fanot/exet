## Объём проверки

Использован полный файл `scenarios/demo_moscow_task.geojson`: 245,149 км², 613 исходных полигонов съёмки, после объединения 570 компонентов, 17 зон и 1837 высотных препятствий. Предоставленных площадок нет; для основной конфигурации планировщик назначает 28 автоматических площадок. Исходная геометрия не упрощалась и не заменялась уменьшенной тестовой областью.

Матрица охватывает все 24 поля `MissionParams`, все значения перечислений и обоих булевых переключателей, значения по умолчанию, характерные числовые значения, допустимые границы и комбинации параметров. Отдельно проверяются ограничения схемы, HTTP API, повторное открытие параметров в интерфейсе и независимая проверка экспортированных траекторий.

Числовые параметры непрерывны, поэтому «все параметры» означает охват всех полей и режимов с выбранными границами, а не перебор каждого числа и полного декартова произведения. Если расчёт прервался на маршрутизации, это отмечается как блокировка дальнейшей проверки данного сочетания. Запуск с `search_effort=thorough` сам по себе не доказывает завершение подробного поиска.

Основная конфигурация: RGB, параметры камеры из каталога, 2 Геоскан 201 + 4 Gemini + 2 Геоскан 801, АКБ из каталога, минимум общего времени, старт 25.09.2026 08:00 +03:00, ветер 5 м/с с 250°, рельеф включён, резерв 20%, высота Солнца ≥10°, временные зоны учитываются, режим с планом полёта, быстрый поиск по сетке. Отклонения для каждого прогона сохранены отдельно.

Во время аудита производственный код расчёта не менялся. Добавлены воспроизводимая матрица и этот отчёт со списком исправлений. Приоритеты, конкретные воспроизведения и критерии готовности: [FIXLIST_MOSCOW_2026-09-29.md](FIXLIST_MOSCOW_2026-09-29.md).

## Проверки API и интерфейса

Обычный набор регрессионных тестов: **166 passed**, одно предупреждение зависимости FastAPI/httpx. При этом интеграционные прогоны на полной Москве нашли ошибки, которые этот набор не выявляет.

Схема `MissionParams` отклонила **66 из 66** специально подобранных некорректных наборов: значения вне диапазонов, неизвестные режимы/модели, пустой и дублированный парк, отрицательные количества, слишком много бортов и АКБ, неверные даты и координаты, NaN/Infinity.

Через `TestClient` проверены **52 корректных HTTP-запроса** с параметрами матрицы: значения нормализованы и переданы исполнителю без потерь. Здесь запуск тяжёлого исполнителя заменён перехватом входа, поэтому это проверка контракта API, а не повторные 52 полных расчёта. Из **44 некорректных HTTP-запросов** 11 вернули ожидаемый 422, а 33 с NaN/±Infinity вернули ошибочный 500. Дополнительные запросы со стандартной JSON-записью `1e309` воспроизвели 500 на `/api/plan`, `/api/advise` и `/api/validate`; загрузка формы на `/api/plan/upload` вернула 422.

Отмена проверена на двух настоящих фоновых задачах с полной московской геометрией, в отдельном хранилище `out/qa_moscow_params/api_isolated`. Отмена была принята во время загрузки рельефа, но ранний отказ планировщика завершил обе задачи статусом `done` и сохранил планы. Ошибка M-05.

Функции `restoreParams`, `params`, обработки часового пояса и направления ветра исполнены из реального `api/static/app.js` в Node с моделью DOM. Восстановление прогнано для матрицы и пяти специальных случаев точности/границ. Подтверждены потеря скрытых настроек, сдвиг UTC, направление 360° после округления и потеря секунд. Дополнительная сверка с каталогом подтвердила изменение перекрытий мультиспектра/лидара при восстановлении `null`.

Реальный обработчик кнопок парка/АКБ отдельно исполнен с объектами событий: восстановленное допустимое значение 20 при «−» или «+» меняется сразу на 12. Этот дефект логики M-14 подтверждён без визуального браузера.

Живой браузер в этой среде не удалось запустить через доступный инструмент; отдельная попытка headless Edge также завершилась отказом доступа. Поэтому визуальное поведение элементов управления и ограничения ползунков ветра/перекрытий оставлены отдельной проверкой, а не объявлены подтверждёнными браузерными дефектами.

## Как читать невыполнимые результаты

«Невыполним» не всегда означает ошибку программы. При ветре 9 и 40 м/с рабочий ветер на высоте исключает все носители; при облачности 51 м не остаётся допустимой рабочей высоты; порог Солнца 60° недостижим для московского задания в выбранное окно. Это ожидаемые ограничения. Ограничение светлого окна также может быть физически обоснованным; наличие такого сообщения само по себе не включено в дефекты.

Другое положение у ошибки «не найден маршрут». Для одного московского соединения точно доказан ложный отказ геометрического маршрутизатора: на тех же конечных точках и запретах расширение числа соседей с 28 до 56 даёт путь 21,63 км без пересечения запретов графа. Полная 4D-траектория по этому контрольному пути не строилась. Другие прогоны с тем же текстом отказа требуют повторной проверки после M-08: общий текст не доказывает одинаковую причину каждого случая.

При построенных траекториях проверка выполняется по экспортированным координатам и времени, включая сегменты между точками и отдельную выборку рельефа. Затем она повторно вызывается на заново прочитанном исходном сценарии. Повторная проверка использует тот же модуль `validate_plan`: это независимость от внутренних структур построителя, а не второй независимо разработанный валидатор.

Полнота покрытия и безопасность — разные свойства. План может пройти все проверки траектории, но снять лишь часть разрешённой площади. Для отчёта сохраняются отдельно `status`, `validation.passed` и `coverage_allowed_pct`; зелёный статус при покрытии менее 95% помечается для разбора. Этот порог — диагностический сигнал, а не критерий приёмки организаторов.

## Воспроизведение и сохранённые данные

Полная матрица:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\qa_moscow_params.py --workers 3 --timeout 1200
```

Повтор одного расчёта:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\qa_moscow_params.py --case 00_baseline --force
```

Повтор нескольких выбранных расчётов:

```powershell
.\.venv\Scripts\python.exe -X utf8 scripts\qa_moscow_params.py --only 07_wind_6_5_east,21_gsd_6,22_gsd_200 --force
```

Данные находятся в `out/qa_moscow_params`:

- `manifest.json`: исходный файл, SHA-256, ревизия, версии пакетов, все наборы параметров и охват полей.
- `<ID>/params.json`, `result.json`, `plan.json.gz`, `progress.json`, `worker.log`: нормализованные настройки, результат, полный план, прогресс и лог отдельного прогона.
- `results.json`: объединённые итоги; `invalid_inputs.json`: проверки схемы.
- `api_probes.json`, `api_edge_cases.json`: HTTP-контракт, некорректные числа, отмена, стек ошибки и конечные состояния задач.
- `ui_roundtrip.json`, `ui_resubmit_validation.json`, `ui_overlap_defaults.json`, `ui_stepper.json`: восстановление, повторная отправка параметров и редактирование количества/АКБ.
- `ignore_temporary_routing_debug.json`, `routing_knn_comparison.json`: проблемное соединение, связность графа и безопасный альтернативный путь.
- `trajectory_diagnostics.json`: высоты на интерполированных сегментах, нарушения у вышек и расхождение эшелонов.

На отдельный полный расчёт установлен предел 1200 секунд. Тайм-аут обозначает ограничение этого аудита, а не доказательство невыполнимости задания. Времена расчёта измерены при трёх параллельных процессах и не предназначены для сравнения производительности алгоритмов.
