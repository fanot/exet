# Рабочий помощник через OpenRouter и Tokenator

## Подключение

Провайдер выбирается через `ASSISTANT_PROVIDER=openrouter` (по умолчанию) или `ASSISTANT_PROVIDER=tokenator`.
Используются только ключ и модель выбранного сервиса. Ключ OpenRouter никогда не отправляется Tokenator и наоборот.

### OpenRouter

1. Скопировать `.env.example` в `.env` в корне проекта.
2. Заполнить `OPENROUTER_API_KEY` своим ключом с балансом OpenRouter.
3. Установить зависимости `python -m pip install -r requirements.txt` и перезапустить API.
4. Открыть «Помощник». Вверху появятся модель и состояние «ключ задан». Отправить короткий вопрос для проверки настоящего ответа.

По умолчанию используется `qwen/qwen3.8-27b`. Модель можно заменить строкой
`OPENROUTER_MODEL=qwen/qwen3.5-27b` или другим совместимым ID с поддержкой tools.
Для бесплатного MiniMax: `OPENROUTER_MODEL=minimax/minimax-m3.1-flash:free`.
У M3.1 Flash рассуждения обязательны: сервер запрашивает низкую интенсивность и общий
бюджет 6000 токенов на рассуждения и ответ. В браузер поступает только итоговый текст;
приватные блоки используются в памяти сервера, если требуется продолжение после вызова кнопки перехода.
В Docker Compose переменные берутся из `.env`; ключ не встраивается в образ.
Пример: `docker compose up --build`. Для запуска Python `.env` автоматически читает сервер.
Переменные окружения процесса имеют приоритет над `.env`.

### Tokenator

В `.env` задайте:

```dotenv
ASSISTANT_PROVIDER=tokenator
TOKENATOR_API_KEY=ваш_ключ_из_кабинета_Tokenator
TOKENATOR_MODEL=gpt-6-luna
```

По умолчанию для Tokenator используется GPT-6 Luna. Не добавляйте префикс `Bearer` к значению ключа.
ID другой модели берётся из каталога Tokenator:
для MiniMax здесь `minimax-m3.1-flash`, без префикса `minimax/` и суффикса `:free`.
Для бесплатного варианта Tokenator использует отдельный ID `free-minimax-m3.1-flash` и суточную квоту.
Модель и доступность для конкретного ключа можно проверить в личном кабинете.

Сервер обращается к `https://api.tokenator.top/v1/chat/completions` с потоковым ответом и tools.
Для MiniMax запрашиваются `reasoning_effort=low` и бюджет 6000 токенов; для остальных моделей — до 2000 выходных токенов.
Для `gpt-6-luna` (алиас `cursor-gpt-6-luna`) сервер задаёт `reasoning_effort=none`:
это необходимый режим для function calling через Chat Completions и экономии токенов на рассуждениях.
В качестве лимита ответа используется `max_completion_tokens=2000`.
Источник совместимости: [OpenAI Docs — GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).
Приватные рассуждения не показываются в браузере. Поддержку конкретной модели нужно проверять настоящим запросом.

После изменения настроек Docker-контейнер нужно пересоздать:

```bash
docker compose up -d --build planner
curl -s https://ваш-домен/api/assistant/status
```

В статусе должны появиться `"provider":"Tokenator"` и `"configured":true`.
Это проверка конфигурации; работоспособность ключа и генерации проверяется вопросом в помощнике.
Контракт провайдера: [документация Tokenator](https://tokenator.top/docs).

### Caddy на VPS и API в Docker

Для Caddy, установленного на том же сервере, в `.env` задайте одновременно:

```dotenv
PLANNER_BIND_HOST=127.0.0.1
FORWARDED_ALLOW_IPS=*
```

Первая настройка публикует порт 8000 только на loopback хоста; вторая позволяет Uvicorn учитывать
`X-Forwarded-Proto` от Caddy, приходящего через Docker-сеть. Пример Caddyfile:

```caddyfile
example.org {
    encode zstd gzip
    reverse_proxy 127.0.0.1:8000
}
```

Без доверия к прокси приложение видит HTTP вместо HTTPS и отклоняет запросы браузера с кодом 403:
«Запрос должен исходить из этого сервиса». Также не выставляется флаг Secure у новой сессии.
Примените настройки через `docker compose up -d --force-recreate planner`.
Значение `FORWARDED_ALLOW_IPS=*` предназначено для конфигурации, где к API обращается доверенный прокси;
в этой схеме его используют вместе с публикацией на `127.0.0.1`.

Ключ не отдаётся клиенту, не хранится в localStorage, не включается в документы или ответы об ошибках.
`.env` исключён из Git и Docker build context. Не добавляйте ключ в скриншоты, логи и коммиты.

## Что знает помощник

В каждый запрос входят:

- обязательная вводная [ASSISTANT_GUIDE.md](ASSISTANT_GUIDE.md);
- до четырёх подходящих выдержек из руководства пользователя, ограничений, моделей энергии,
  воздушного пространства и формата зон; подбор по словам вопроса и русским основам слов;
- текущие настройки формы (помечены как непроверенный черновик);
- параметры, показатели, проверки, проблемы, замечания и рекомендации выбранного плана;
- краткие параметры выбранного вылета, если он выделен;
- последние реплики диалога в пределах 24 тысяч символов.

Сервер загружает выбранный план сам и проверяет принадлежность сессии. Клиент не может
подсунуть чужой план или произвольный документ. Полная геометрия и точки маршрута не отправляются.
Документы перечислены явно в `api/assistant.py`; произвольное чтение файлов не поддерживается.
Выдержки помечены `[D1]`, `[D2]` и т.д.; ссылки в ответе открывают документ сервиса.
После изменения документации перезапустите сервер: текст кэшируется в памяти процесса.

Модель видит только переданный контекст, поэтому для подробного вопроса о вылете нужно его выбрать.
Черновик может отличаться от последнего плана. После изменения настроек нужен новый расчёт.

## Взаимодействие

Ответ поступает потоком. Его можно остановить и повторить; при ошибке показана причина.
Enter отправляет, Shift+Enter добавляет строку. «Новый диалог» очищает реплики этой вкладки.
Смена плана или настроек обновляет контекст, сохраняя разговор. История не записывается на сервер.
Модель может предложить кнопки перехода к парку, съёмке, условиям, оптимизации,
обзору, проверкам, геометрии, файлам или истории. Клик раскрывает и подсвечивает нужный раздел.
Помощник не меняет параметры, не запускает расчёт, не удаляет планы и не управляет аппаратами.

## Ограничения и эксплуатация

- Статус «ключ задан» означает наличие ключа без очевидных ошибок формата, а не проверенный баланс или доступность провайдера.
- В Render значение ключа вставляется без `Bearer`, кавычек и префикса `OPENROUTER_API_KEY=`. Изменения применяются через Save and deploy.
- Ошибки помощника содержат название выбранного сервиса и его HTTP-код. 401 — отказ аутентификации; 403 — ограничения доступа, фильтров или бюджета. 403 не означает, что сам ключ неверен.
- В логах сервиса сохраняются только HTTP-код и фиксированная категория ошибки; исходный ответ провайдера, ключ и текст вопроса не журналируются.
- Ошибки ключа, баланса, модели, сети и ограничения провайдера показываются без его сырого ответа.
- Лимиты: 8 вопросов в минуту на сессию, один текущий ответ на сессию,
  до 12 активных ответов на процесс, 2000 выходных токенов (для M3.1 Flash — 6000 вместе с рассуждениями)
  и до 100 секунд на генерацию.
- Отмена закрывает HTTP-поток к провайдеру; фактический учёт токенов зависит от выбранного сервиса.
- Лимиты находятся в памяти одного процесса. Для нескольких workers нужен общий ограничитель.
- Настройки, сводка и сообщения передаются выбранному сервису (OpenRouter или Tokenator) и его провайдеру модели. Название сервиса показано в панели помощника.
- Выводы LLM могут содержать ошибки. Успешный расчёт не является разрешением на реальный полёт.
- Модель не получает живую погоду, актуальные NOTAM и фактическую телеметрию.

Контракт API: `GET /api/assistant/status`, `GET /api/assistant/docs/{slug}`,
`POST /api/assistant/chat`. Последний возвращает SSE-события `meta`, `delta`, `action`,
`notice`, `done`, `error`. До начала потока ошибки доступа и конфигурации имеют HTTP 404/503/429/422.
После начала ошибки передаются событием `error`, а не успешным `done`.

Проверка без расходов на модель: `python -m pytest tests/test_assistant.py`.
Тесты подменяют только HTTP-транспорт провайдеров; production-код использует реальные endpoint.
Для проверки качества после подключения ключа задайте вопросы о первом запуске, балансе,
причине непройденной проверки, текущем ветре и влиянии перекрытий; сверьте числа с планом.

Интеграция использует [Chat Completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request)
и [tool calling](https://openrouter.ai/docs/guides/features/tool-calling) OpenRouter.
