## Поток данных

1. **Вход.** Принимаются GeoJSON FeatureCollection или KML в WGS-84. Слой объекта задается полем `properties.kind`, в KML — через ExtendedData или по названию папки. Геометрия проверяется: невалидные контуры исправляются через `make_valid`, проверяются диапазоны координат и лимиты на размер.
2. **Локальная СК.** Используется азимутальная равнопромежуточная проекция с центром в сценарии, все расчеты идут в метрах. На выходе координаты снова в WGS-84.
3. **Планирование** (см. [ALGORITHM.md](ALGORITHM.md)). Результат — JSON плана: сводка, типы БВС, борта, вылеты с 4D-точками `[lon, lat, alt_amsl, alt_agl, t, phase]`, рекомендации, журнал поиска.
4. **Проверка.** `validate.py` заново читает только выходные точки. Проекция у него своя, от планировщика он не зависит. Проверки те же, что будет делать жюри.
5. **Экспорт.** GeoJSON/KML/CSV/QGC строятся из JSON плана без пересчета. Тот же план режется по бортам (`?drone=`) — индивидуальные задания.
6. **Ход расчета.** Задача выполняется в фоновом потоке. `/api/jobs/{id}` отдает этап, время, число оценок и сходимость поиска (лучший вариант после каждой оценки) прямо из журнала планировщика; отмена — флаг, который проверяется в колбэке прогресса. Вместе с планом сохраняется исходный сценарий: план из истории открывается со своей картой и параметрами.

## Решения и обоснование

- **Python + shapely/pyproj/numpy.** Для этой задачи стандарт; горячие циклы векторизованы: сканлайн, 4D-проверка, выборка ЦМР.
- **Без БД.** Планы — JSON-файлы в томе `data/`, этого хватает для истории и сравнения. PostGIS избыточен при масштабе ~100 км² и ≤ 10 бортов.
- **Долгий расчет — фоновая задача с прогрессом.** Ограничение QA «≤ 30 мин» выполняется: демо считается за секунды, нормальный поиск — до ~1–2 мин.
- **Интерфейс без сборки** (vanilla JS + Leaflet). Контейнер один, на офлайн-сборку не завязан; интернет нужен только для подложки карты и ЦМР (QA: интернет есть).
- **Каталог ТТХ в YAML.** Эксперт может поменять перекрытия, буферы, число АКБ или шаг эшелонов без правки кода. Допущения помечены полем `assumption`.
